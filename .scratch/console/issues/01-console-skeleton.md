# 01: Console skeleton: sidebar, themes, Settings and CI

**What to build:** A developer runs the PayBridge Console (`@paybridge/console`) from the monorepo and sees the application shell built from the shadcn **sidebar-08** block (Base UI flavour): the header "PayBridge Console", every navigation item from the spec, the secondary nav and the Operator user menu in the footer. Every page except Refunds exists as a placeholder with a breadcrumb. The Operator can switch light, dark and system themes, collapse the sidebar, and use it as a drawer on a phone. Settings already works: theme and table density are remembered in the browser, and a read-only Environment panel shows the API base URL, whether mock mode is on, and the build version. The Console is held to the same standard as the API: it builds, lints, typechecks and runs its tests in turbo and in CI.

See [spec](../spec.md): Navigation and layout, Settings, Platform and quality; Implementation Decisions › Application, Sidebar, Routing.

## Answer

`apps/console` (`@paybridge/console`) is a Next.js 16 App Router app with strict TypeScript (new shared `@paybridge/typescript-config/next.json`), Tailwind 4 and shadcn/ui (base-nova, Base UI) generated by the CLI. The shell is the sidebar-08 block adapted: navigation lives in `src/lib/navigation.ts` (Refunds has no `url`, so it renders as a disabled "Soon" button), the footer Operator menu has the light, dark and system switch (next-themes, class strategy, no flash). `PageHeader` gives every placeholder page a breadcrumb derived from the navigation. Settings keeps theme (next-themes) and table density (`src/lib/preferences.ts`, read defensively) in browser storage; the Environment panel gets `CONSOLE_API_BASE_URL`, `CONSOLE_API_MOCKS` and the package version from a server component (`src/lib/environment.ts`, `server-only`), and the built client bundle does not contain the URL. Vitest (jsdom, Testing Library) and Playwright (against `next start` in mock mode) are configured; `build`, `lint` (oxlint type-aware), `typecheck`, `test` and `test:e2e` run through turbo, and CI builds the Console and runs Playwright. Not done here by design: the Exceptions open-count badge, the mock banner and the auth seam (later tickets); the footer identity is a static "Operator".
